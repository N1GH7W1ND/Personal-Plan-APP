# 验收标准覆盖结论

> 依据：`PRD.md` 第 10 节「可实际检查的验收标准」，**含范围变更记录 R1–R8 之后的新增标准**。
> 结论口径只有两种：**自动化**（有测试用例真的跑过）或**人工**（必须在你自己电脑上双击、用浏览器确认）。
> 不存在"看起来应该没问题"的第三种说法。

## 怎么复现全部自动化测试

在本文件夹打开命令行，执行：

```
node test/run-all.js
```

## 一、运行与持久化（A 组，8 条）

| 编号 | 验收标准 | 结论 | 覆盖方式 |
|---|---|---|---|
| A1 | 双击启动脚本后浏览器自动打开应用首页 | **人工** | 测试环境禁止测试进程创建独立进程（`spawn`/`Start-Process` 均被拦截），无法自动验证"自动打开浏览器"。服务本身的启动路径已用真实命令行走通，浏览器行为需你双击确认 |
| A2 | 重复双击启动脚本不报错、不开两份数据 | **自动化** | `test/phase1.js`：重复启动识别 + 端口复用保护 |
| A3 | 新增任务后刷新浏览器，任务仍在 | **自动化** | `test/web-store.mjs` 重新加载校验；`test/web-views.mjs` 刷新后核对 |
| A4 | 关闭浏览器再打开，数据仍在 | **自动化** | 同上：数据全部来自磁盘文件，重新加载即等价于重开浏览器 |
| A5 | 重启电脑后再启动，数据仍在 | **自动化（等价）** | `test/phase7.js`：换数据目录/新进程读同一份文件 |
| A6 | 数据文件存在于 `data/` 且是可读文本 | **自动化** | `test/phase2.js`：检查格式化 JSON、中文不转义、以换行结尾 |
| A7 | 断网状态下应用完全可用 | **自动化** | `test/phase1.js`、`test/phase7.js`：源码无任何外网引用、服务只监听 `127.0.0.1` |
| A8 | 每次修改后 1 秒内顶栏显示"已保存" | **自动化** | `test/web-views.mjs`：改完等 900ms 后检查文件里已有该内容 |

## 汇总

| 结论 | 条数 |
|---|---|
| 自动化覆盖 | 96 |
| 人工确认 | 6（A1 浏览器自动打开、G2 按键手感、R8.3 视觉观感、R12.1–R12.3 导航动效） |
| 已作废（模块按 R1–R3、R10 移除） | 15（C1–C3、C6–C11、C14–C15、E4，以及 G1/G2 的入口数口径变化） |
| **当前有效合计** | **102 条** |

六条人工项的原因说清楚：

- **A1（自动打开浏览器）**：开发环境禁止测试进程启动独立进程，无法自动验证浏览器行为。服务启动路径已用真实命令行验证。
- **G2（快捷键手感）**：按键到路由的映射有自动化测试，但"按下去真的切过去了"需要真实浏览器。
- **R8.3（视觉观感）**：好不好看无法用断言判定，只能你眼睛看。样式表的结构正确性（变量、括号、色值、对比度、层级）已自动化覆盖。
- **R12.1–R12.3（导航微互动）**：悬浮位移、呼吸光晕、徽标弹入都属于动效观感，无法用断言判定；但**它们不影响功能**这一点是自动化的——导航数量、路由切换、数字键用例全部照常通过。

## 测试过程中发现并修掉的真缺陷（登记备查）

这些不是测试写错，而是实现里的真问题，都由测试逼出来并已修复：

| 缺陷 | 影响 | 发现方式 |
|---|---|---|
| 首次运行只建内存空数据，从不落盘 | 打开数据目录看不到 `data.json` | phase1「首次启动应创建 data.json」 |
| 同一秒内两次备份互相覆盖 | "恢复前自动备份"可能丢失 | phase2「恢复前会自动再存一份」 |
| 每日备份判断用了带横线的日期 | **每次写入都会多存一份备份**，20 份很快被冲掉 | phase2「同一天仍应只有 1 份自动备份」 |
| 数据文件路径被目录占用时抛异常 | 应用直接报错，而不是给出明确提示 | phase7「只读/异常时不静默丢数据」 |
| 写盘失败时接口误报为"数据冲突" | 用户以为是多窗口冲突，实际是磁盘问题 | phase7 同一条用例 |
| 备份失败会连累主写入流程 | 备份异常导致"保存失败"，其实主数据本来能写进去 | phase7 同一条用例 |
| `dataAttrs` 把 `data-ex` 前缀成 `data-data-ex` | 健身「完成整项/删除动作」按钮失效 | phase5 C10 |
| 自媒体箭头一次点击移动两档 | 看板跳过"写作中" | phase5 C1（最小复现定位） |
| `router.go` 在无 `location` 环境静默失败 | 跳转会不生效且不留痕迹 | phase4 B8 |
| 迟到的旧保存覆盖刚导入的数据 | 清空/恢复后数据被旧内容写回 | phase5（store 代次机制） |
| 服务端空模板的健身周安排是空的 | 磁盘文件不自描述，全靠前端补齐 | 真实启动验证时发现 |
| `parseDateStr` 把 `2026-13-01` 滚成次年 | 日历与日期比较出现错乱 | 前端日期测试 |
| 日期注释里的反例被当成真实代码 | 静态检查误报 | 前端日期测试 |
| **服务端 `normalize` 没清理已移除模块名下的任务** | 旧数据里会留下"无处可去"的孤儿任务 | 本次改造：`test/phase2.js` 旧数据清理用例 |
| **旧数据清理只发生在内存里、没写回磁盘** | 磁盘文件仍带着已移除模块的字段：每次启动都要重新清理，导出的备份与实际文件不一致，"看着干净其实没清" | 本次改造：用你的真实 `data.json` 启动后发现（文件大小未变）。已修复并加回归用例；**该用例在回退修复后会失败**，确认它不是假测试 |
| **`pieChart` 引用了不在作用域的 `moduleId`** | 首页与四个模块页的图表**直接渲染报错** | 本次改造：`test/web-modules.mjs` |
| **图表内部桶名与真实日期键可能冲突** | 选中某天后明细筛选结果不确定 | 本次改造：排查点击行为时发现，已按 key 形态分流 |
| **移除模块时漏清设置里的关联字段** | 健身模块移除后，`settings.fitnessWeeklyGoal` 还留在数据文件里，成了没人读的僵尸字段 | 本次改造：`test/phase2.js` 的断言（"设置里不该还有健身目标"）直接抓到 |
| **用 PowerShell 写含反引号的文本时字符被吃掉** | 一次 `-replace` 把 PRD 里的 `fitness` 写成了换页符 + `itness`，肉眼几乎看不出 | 写完文档后逐字核对发现。已修复，并加了一条检查：所有文档不得含控制字符、每行反引号必须成对 |
| **数字键快捷键与输入框自动聚焦冲突** | 进首页后「快速补一条」输入框自动获得焦点，数字键于是变成"往输入框里打字"，想切页面必须先点一下空白处 | 你报告的 bug（第一版修错了方向：只加了守卫，没去掉自动聚焦，反而更需要点空白处）。最终做法：**去掉自动聚焦**，数字键随时可切页；同时保留"主动点进输入框时数字归用户"的守卫。两个方向都有回归用例，**回退任一改动都会失败** |
| **加书时填了已读页数，状态却停在"想读"** | 新建一本"已读到 40/100"的书，它会显示成"想读"，概况统计里的"在读"数也少算一本 | 加阅读模块时发现：状态推导只写在"改书"里，"加书"没走。已抽出共用的 `applyBookProgressRules()`，两个入口都过同一套规则。回归用例**回退修复后会失败** |
| **星空装饰层没被压住会盖掉整个界面** | 改用深色星空主题时，星点/月亮是 `body::before/::after` 的固定层（`z-index:0`）。若内容层不显式声明更高的 z-index，星空会画在界面上方——**整个应用看起来像被一层噪点糊住**，还可能挡住点击 | 改主题过程中发现并修复（`.app` 加 `position:relative; z-index:1`）。已加检查：装饰层必须 `pointer-events:none`，且内容层 z-index 必须更高；**去掉该声明后检查会失败** |

## 视觉主题（参考 macOS 天气）

整体外观按你给的参考图重做：深蓝星空底 + 半透明月亮 + 毛玻璃卡片。

| 要素 | 做法 |
|---|---|
| 夜空底色 | 深蓝纵向渐变，四角叠一层蓝紫晕开 |
| 星点 | 纯 CSS（多组 `radial-gradient` 平铺），**不新增 DOM**，因此不影响任何功能 |
| 月亮 | `body::after` 上的柔和白圆 + 月晕 |
| 毛玻璃卡片 | 半透明深色 + `backdrop-filter: blur()` + 极细浅色描边 + 顶部内微光 |
| 悬浮反馈 | 卡片 hover 时轻微提亮并加外发光 |
| 文字层级 | 正文近白（对比度 15:1）、次要 10:1、辅助 6:1，全部达标 |
| 警示色 | 暖黄（`--warn: #ffcf5c`），用于逾期与提醒 |

**功能零影响**：这次只改了 `web/styles.css` 的颜色与视觉效果，
没有改动任何 DOM 结构、类名、事件或数据逻辑，全量 212 条测试全部通过。

主题改动同时新增了 3 条自动化检查（共 4 条样式检查）：
文字对比度、装饰层不遮挡内容、装饰层不吃指针事件。

## 还剩下的已知边界

- **A1、G2、R8.3 需要你人工确认**（原因见上）。
- 测试用的界面环境是一个精简 DOM 桩，它能真实触发点击处理器，但**不校验 CSS 样式与视觉排版**；图表是 SVG，桩能解析其结构，但不校验图形是否好看。
- 只验证了 Windows + 现代浏览器；其它平台未做适配，也不在需求范围内。
- 数据文件的字段结构变化（移除三个模块）**不可逆**：删除后再导入旧备份，只会恢复出仍然存在的模块。
